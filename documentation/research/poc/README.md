# PoC: экстрактор стилей из DOCX

Рабочий прототип к исследованию [#8 «Как вытягивать стили из DOCX»](../docx-style-extraction.md):
читает `.docx` и выдаёт нормализованный JSON с описанием оформления. Написан на одной стандартной
библиотеке (`zipfile` + `xml.etree`) — намеренно, чтобы показать: базовая выжимка стилей не требует
тяжёлых зависимостей и переносима на любой стек.

## Что делает

- Читает OPC-контейнер: `styles.xml`, `theme1.xml`, `numbering.xml`, `document.xml`, `settings.xml`,
  `docProps/*`.
- Нормализует единицы (half-point → pt, dxa → мм) и разыменовывает ссылки на тему
  (`asciiTheme="minorHAnsi"` → реальный шрифт).
- Строит список стилей плюс «эффективный» стиль: `docDefaults` → цепочка `basedOn` → собственные свойства,
  то есть то, что реально видит рендерер.
- Считает долю прямого форматирования в теле документа — главный индикатор того, ловится ли оформление
  стилями или задано «руками».
- Собирает список необработанных элементов (`unsupported`), чтобы честно показать границы PoC.

## Как запустить

```bash
python3 docx_style_extract.py file.docx -o out.json
python3 docx_style_extract.py file.docx            # JSON в stdout
python3 docx_style_extract.py file.docx --no-effective   # без расчёта эффективных стилей
```

Проверялось на Python 3.13. Внешних зависимостей нет; LibreOffice и pandoc не требуются.

## Границы

Это не полноценный парсер DOCX: покрытие ограничено набором свойств, которые перечислены в `RPR_KNOWN`
и попадают в результат, всё остальное складывается в `unsupported`. Мержинга документов, трекинга
изменений и работы со встроенными объектами здесь нет.

Что из этого следует для продукта, какие цифры получены на реальных шаблонах и какие решения приняты —
в исследовании [«Извлечение стилей из DOCX»](../docx-style-extraction.md).
