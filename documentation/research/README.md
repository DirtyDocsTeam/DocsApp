# Исследования

Раздел для исследований, которые отвечают на конкретный вопрос задачи и заканчиваются выводом «что делать».
Отличие от обзорных заметок: здесь нужны проверенные цифры, ссылка на первоисточник и явное разделение
«проверено / не проверено».

Каждый отчёт открывается задачей из issue-трекера, содержит TL;DR, метод и ограничения, а в конце —
открытые вопросы. Если цифра не проверялась локально, это сказано прямо в тексте.

## Отчёты

| Задача | Страница | О чём и главный вывод |
|---|---|---|
| [#8](https://github.com/DirtyDocsTeam/DocsApp/issues/8) — как вытягивать стили из DOCX | [`docx-style-extraction.md`](docx-style-extraction.md) | Прямой разбор OOXML (`styles.xml`, `theme1.xml`, `numbering.xml`, `sectPr`) на stdlib: ~87 мс на файл 1.1 МБ. Нужны две выжимки — именованные стили и статистика фактического форматирования, потому что в живом ГОСТ-шаблоне 78 % абзацев имеют `pStyle`, а `Normal` не используется вовсе. Обязателен маппинг «стиль → роль». LibreOffice — нормализатор входа и оракул, но не источник стилей; pandoc стили не переносит |
| [#11](https://github.com/DirtyDocsTeam/DocsApp/issues/11) — реализация из «Книга в Markdown» | [`book-to-markdown-approach.md`](book-to-markdown-approach.md) | Переносить надо механизм, а не шаблон: один AST → несколько выходов (DOCX/PDF/сайт). Без pandoc дорого стоят только формулы (LaTeX → OMML) и DOCX-writer с шаблоном. Их `template.docx` — не ГОСТ 7.32-2017, поэтому эталон берём из #8 |

## Как добавить отчёт

- Файл: `research/<тема-латиницей-через-дефисы>.md` → страница `research--<имя-файла>`.
- В заголовке — номер задачи и ссылка на issue; в начале — блок «Задача / Источник / Метод».
- TL;DR в начале, «что проверено и как» — по ходу, «что осталось непроверенным» и открытые вопросы — в конце.
- Большие вложения и скрипты складывать рядом (`research/poc/…`), они попадут в инвентарь артефактов.
- Не переносить в документацию чужие тексты целиком: цитаты — короткие, со ссылкой на источник.
