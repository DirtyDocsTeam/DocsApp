# Дизайн и проектирование

Раздел про архитектуру DocsApp: из чего состоит система, какие протоколы между частями и как устроены
данные. **Источник правды — C4-диаграмма контекста**; ERD, `db.sql` и остальные документы сверяются с ней,
а расхождения собраны в одном месте и считаются отклонениями.

## Что здесь есть

| Файл | Что это |
|---|---|
| [`design.md`](design.md) | основная страница раздела: расшифровка C4, таблица отклонений артефактов от неё, модель данных, дефекты черновика DDL и открытые вопросы |
| [`context.drawio`](context.drawio) | **C4-диаграмма контекста — источник правды** по архитектуре: участники, контейнеры, протоколы (редактируется в diagrams.net / draw.io) |
| [`context.jpg`](context.jpg) | экспорт диаграммы для быстрого просмотра |
| [`schema.svg`](schema.svg), [`schema.png`](schema.png) | ERD: 12 таблиц PostgreSQL |
| [`db.sql`](db.sql) | черновик DDL под ERD: проектный референс, **не** миграция |

## Как читать

1. Открыть C4-диаграмму — это рамка, в которой принимаются все решения: `Ingress` (HAProxy), `IDProvider`
   (Keycloak), `Main API Plane`, `S3 Gateway Plane`, объектное хранилище и пул воркеров `WorkerC/V/T/G`.
2. Прочитать [`design.md`](design.md) — там расшифровка контейнеров и связей, затем таблица «Соответствие
   артефактов C4»: что в baseline, ERD или `db.sql` ещё говорит иначе.
3. Смотреть модель данных по ERD; `db.sql` держать рядом как черновик DDL, но не как истину.

## Правила раздела

- Архитектурное изменение начинается с C4: правится `context.drawio`, затем обновляется экспорт
  `context.jpg` и таблица соответствия в [`design.md`](design.md).
- ERD и `db.sql` меняются вместе; после стабилизации схемы — переход на миграции, текущий черновик
  к миграциям не готов.
- Требования задаёт ТЗ (ссылки — в [`design.md`](design.md)), архитектуру — C4; если они расходятся,
  это фиксируется, а не сглаживается.

## Статус

C4 — актуальная. Модель данных — черновик: ERD и `db.sql` между собой синхронизированы, но у DDL есть
дефекты, из-за которых он не выполнится, и не выражены retention, отчёты и отзыв токенов.
Полный список — в [`design.md`](design.md#дефекты-черновика-dbsql).
