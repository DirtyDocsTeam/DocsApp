# Дизайн и проектирование

Раздел про архитектуру DocsApp: из чего состоит система, какие протоколы между частями и как устроены данные.
**Источник правды — C4-диаграмма контекста**; ERD, `db.sql` и остальные документы сверяются с ней, а расхождения собраны в одном месте и считаются отклонениями.

## Что здесь есть

| Файл | Что это |
|---|---|
| [`design.md`](design.md) | основная страница раздела: расшифровка C4, таблица отклонений артефактов от неё, модель данных, дефекты черновика DDL и открытые вопросы |
| [`context.drawio`](context.drawio) | **C4-диаграмма контекста — источник правды** по архитектуре: участники, контейнеры, протоколы (редактируется в diagrams.net / draw.io) |
| [`context.jpg`](context.jpg) | экспорт диаграммы для быстрого просмотра |
| [`schema.svg`](schema.svg) | Основной ERD: статичная SVG-диаграмма с автоматической раскладкой таблиц; собирается из чанжлога (`make db-erd`) |
| [`erd.md`](erd.md) | Текстовый ERD на Mermaid и таблица внешних ключей; собирается из чанжлога (`make db-erd`) |
| [`db.sql`](db.sql) | DDL, собранный из Liquibase-чанжлога (`make db-schema`); не правится руками |

## Как читать

1. Открыть C4-диаграмму — это рамка, в которой принимаются все решения: `Ingress` (HAProxy), `IDProvider`   (Keycloak), `Main API Plane`, `S3 Gateway Plane`, объектное хранилище и пул воркеров `WorkerC/V/T/G`.
2. Прочитать [`design.md`](design.md) — там расшифровка контейнеров и связей, затем таблица «Соответствие  артефактов C4»: что в baseline, ERD или `db.sql` ещё говорит иначе.
3. Смотреть модель данных по [`schema.svg`](schema.svg); `erd.md` оставлен как текстовая альтернатива, а `db.sql` — как черновик DDL.
