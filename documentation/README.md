# DocsApp

Сервис оформления документов: на входе Markdown или шаблон DOCX, на выходе
DOCX / PDF / ODT с соблюдением стилей — библиотека тем и коллекций стилей, извлечение стилей из готовых документов, валидация оформления до рендера, публичный API с токенами.

## Как добавить страницу

- Кладите файл в `documentation/<раздел>/<имя>.md` и коммитьте в `main` — вики обновится сама.
- Имя файла — латиница, цифры, дефисы: `documentation/research/docx-style-extraction.md`.
  Имя страницы собирается из пути: `research/docx-style-extraction.md` → `research--docx-style-extraction`.
- `README.md` (или `index.md`) внутри подраздела становится лендингом раздела:
  `documentation/research/README.md` → страница `research`, первой в навигации.
- Всё, что не `.md` (картинки, `.drawio`, `.pdf`, `.sql`, PoC-скрипты), считается артефактом: попадает  в авто-блок «Файлы в этой папке» своей страницы и в общий инвентарь **Artifacts**. В авто-перечислении  всё показывается ссылкой на файл в репозитории, без встраивания; `png`/`svg` рядом с `.drawio`  трактуется как предпросмотр диаграммы и отдельной строкой не дублируется.
- Относительные ссылки переписываются автоматически: `.md` → страница вики (или blob-ссылка, если файл  не публикуется), изображения → raw-URL, прочие файлы → ссылка на репозиторий.  Ссылки за пределы `documentation/` оставляйте абсолютными — относительные в вики сломаются.
- Файлы, начинающиеся с точки, и страницы без маркера `wiki-sync:managed` синхронизатор не трогает:  страницы, созданные в вики руками, не удаляются.

## Как обновляется вики

- **Автоматически:** push в `main` с изменениями в `documentation/**`, в скрипте синхронизации или в самом  workflow. Дополнительно: ручной запуск (`workflow_dispatch`) и еженедельное расписание  (понедельник, 06:00 UTC) — чтобы подтянуть даты последних коммитов в индекс страниц.
- **Workflow:** `.github/workflows/docs-wiki-sync.yml`, генератор — `.github/scripts/wiki_sync.py`  (только стандартная библиотека Python).
- **Контракты API собираются перед синхронизацией:** шаг `make api-docs` (скрипт
  `.github/scripts/api_docs.py`) перегенерирует `documentation/api/` из кода — REST по аннотациям  Jakarta REST, GraphQL по MicroProfile GraphQL, gRPC по `.proto`; готовые OpenAPI (JSON) и SDL  из сборки имеют приоритет. Для сервисов без кода/аннотаций поддерживается декларативный  YAML-контракт рядом с сервисом (`framework = "api-contracts"`, пример —  `backend/s3-gateway/api-contracts.yaml`). Правила сбора и список источников — в  [`api-docs.toml`](../api-docs.toml), руками эти страницы не правятся. Если сборка контрактов  падает, вики не перезаписывается.
- **Что нужно один раз настроить в репозитории:** включённая Wiki с хотя бы одной страницей, созданной  через UI (иначе git-репозитория `<repo>.wiki.git` не существует), и секрет `WIKI_TOKEN` — классический  PAT со scope `repo` (fine-grained-токены прав на вики не дают).
- **Локальный предпросмотр** без публикации (флаг `--wiki /tmp/wiki` пишет в указанную папку вместо  клонирования вики, `--push` добавляет коммит и пуш; по умолчанию скрипт клонирует вики по `WIKI_TOKEN`
  и пушит изменения):

```bash
make docs-preview      # = make api-docs + wiki_sync в /tmp/wiki-dry
make api-docs-check    # проверить, что страницы контрактов соответствуют коду
```

## Чего в каталоге быть не должно

- Секретов, токенов, ключей и конфигурации окружений.
- Документов пользователей и персональных данных: примеры и фикстуры — обезличенные и минимальные.
- Крупных бинарников и сгенерированных артефактов сборки — для них есть внешнее хранилище.
- Правок только в вики: следующий запуск синхронизации их перезапишет.
- Правок руками в `documentation/api/`: каталог генерируется и не коммитится — меняйте код или
  [`api-docs.toml`](../api-docs.toml).

## Статус разделов

- `design/` — диаграммы и схема БД. Источник правды по архитектуре — C4-контекст
  (`design/context.drawio`); схема — Liquibase-чанжлог `backend/api/src/main/resources/db/changelog`.
  Из чанжлога собираются `design/db.sql` (`make db-schema`), SVG ERD `design/schema.svg` и текстовый Mermaid
  `design/erd.md` (`make db-erd`) —
  руками эти файлы не правятся. Открытые расхождения и дефекты DDL перечислены
  в [`design/design.md`](design/design.md).
- `api/` — генерируется, в репозитории не хранится: `make api-docs` собирает контракты из кода
  по правилам [`api-docs.toml`](../api-docs.toml) перед каждой публикацией вики.
- `research/` — исследования с проверенными цифрами и PoC-скриптом экстрактора стилей.
- `qa/` — пока пусто; тест-кейсы и отчёты ревью по основной конверсии складывать сюда.
