# DocsApp

Сервис оформления документов: на входе Markdown или шаблон DOCX, на выходе
DOCX / PDF / ODT с соблюдением стилей — библиотека тем и коллекций стилей, извлечение стилей из
готовых документов, валидация оформления до рендера, публичный API с токенами.

- Код, схема БД и ERD: [DirtyDocsTeam/DocsApp](https://github.com/DirtyDocsTeam/DocsApp)
- Требования и задачи: [issues](https://github.com/DirtyDocsTeam/DocsApp/issues)
- Продуктовый baseline: [`.agents/PROJECT.md`](https://github.com/DirtyDocsTeam/DocsApp/blob/main/.agents/PROJECT.md)

Этот каталог — источник правды для документации: вики собирается из него автоматически
(workflow `docs → wiki`), правки в вики перезаписываются.

## Структура каталога

| Путь | Что внутри | Куда попадает в вики |
|---|---|---|
| `README.md` | этот файл: описание проекта и правила работы с каталогом | содержание страницы **Home** (отдельной страницей не публикуется) |
| `design/` | архитектура: [диаграмма контекста, отклонения от неё, ERD и черновик схемы БД](design/design.md) | страница `design--design` + страница **Artifacts** для картинок и `db.sql` |
| `research/` | исследования с проверенными цифрами и PoC: извлечение стилей из DOCX, конвейер «книга → Markdown» | страницы `research--<имя-файла>` |
| `qa/` | пусто: место для чек-листов, тест-кейсов и отчётов ревью | появится, когда в каталоге будут `.md` |
| `.wikiignore` | необязательный файл: по одному fnmatch-шаблону на строку, что не синхронизировать | — |
|...|...|...|

## Как добавить страницу

- Кладите файл в `documentation/<раздел>/<имя>.md` и коммитьте в `main` — вики обновится сама.
- Имя файла — латиница, цифры, дефисы: `documentation/research/docx-style-extraction.md`.
  Имя страницы собирается из пути: `research/docx-style-extraction.md` → `research--docx-style-extraction`.
- `README.md` (или `index.md`) внутри подраздела становится лендингом раздела:
  `documentation/research/README.md` → страница `research`, первой в навигации.
- Всё, что не `.md` (картинки, `.drawio`, `.pdf`, `.sql`, PoC-скрипты), считается артефактом: попадает
  в авто-блок «Файлы в этой папке» своей страницы и в общий инвентарь **Artifacts**. Изображения
  встраиваются, остальное линкуется; `png`/`svg` рядом с `.drawio` трактуется как предпросмотр диаграммы
  и отдельной строкой не дублируется.
- Относительные ссылки переписываются автоматически: `.md` → страница вики (или blob-ссылка, если файл
  не публикуется), изображения → raw-URL для встраивания, прочие файлы → ссылка на репозиторий.
  Ссылки за пределы `documentation/` оставляйте абсолютными — относительные в вики сломаются.
- Файлы, начинающиеся с точки, и страницы без маркера `wiki-sync:managed` синхронизатор не трогает:
  страницы, созданные в вики руками, не удаляются.

## Как обновляется вики

- **Автоматически:** push в `main` с изменениями в `documentation/**`, в скрипте синхронизации или в самом
  workflow. Дополнительно: ручной запуск (`workflow_dispatch`) и еженедельное расписание
  (понедельник, 06:00 UTC) — чтобы подтянуть даты последних коммитов в индекс страниц.
- **Workflow:** `.github/workflows/docs-wiki-sync.yml`, генератор — `.github/scripts/wiki_sync.py`
  (только стандартная библиотека Python).
- **Что нужно один раз настроить в репозитории:** включённая Wiki с хотя бы одной страницей, созданной
  через UI (иначе git-репозитория `<repo>.wiki.git` не существует), и секрет `WIKI_TOKEN` — классический
  PAT со scope `repo` (fine-grained-токены прав на вики не дают).
- **Локальный предпросмотр** без публикации (флаг `--wiki /tmp/wiki` пишет в указанную папку вместо
  клонирования вики, `--push` добавляет коммит и пуш; по умолчанию скрипт клонирует вики по `WIKI_TOKEN`
  и пушит изменения):

```bash
python3 .github/scripts/wiki_sync.py --out /tmp/wiki-dry --no-dates
```

## Чего в каталоге быть не должно

- Секретов, токенов, ключей и конфигурации окружений.
- Документов пользователей и персональных данных: примеры и фикстуры — обезличенные и минимальные.
- Крупных бинарников и сгенерированных артефактов сборки — для них есть внешнее хранилище.
- Правок только в вики: следующий запуск синхронизации их перезапишет.

## Статус разделов

- `design/` — диаграммы и **черновик** схемы БД. Источник правды по архитектуре — C4-контекст
  (`design/context.drawio`); отличия остальных артефактов от него и дефекты черновика DDL перечислены
  в [`design/design.md`](design/design.md). ERD и `db.sql` между собой синхронизированы, но DDL не готов
  к миграциям.
- `research/` — исследования с проверенными цифрами и PoC-скриптом экстрактора стилей.
- `qa/` — пока пусто; тест-кейсы и отчёты ревью по основной конверсии складывать сюда.
