# Как вести документацию

Правила каталога `docs/`: куда класть файл, что собирается скриптами и как изменения попадают
в GitHub Wiki. Что читать как документацию о проекте — на [главной странице](README.md).

## Принцип

Источник правды — репозиторий. Вики — витрина: её страницы генерируются из `docs/**` и
перезаписываются при каждом запуске синхронизации, поэтому правки в вики живут до следующего коммита.

## Как добавить страницу

- Кладите файл в `docs/<раздел>/<имя>.md` и коммитьте в `main` — вики обновится сама.
- Имя файла — латиница, цифры, дефисы: `docs/research/docx-style-extraction.md`.
  Имя страницы собирается из пути: `research/docx-style-extraction.md` → `research--docx-style-extraction`,
  вложенность растёт так же (`a/b/c.md` → `a--b--c`).
- `README.md` (или `index.md`) внутри подраздела становится лендингом раздела:
  `docs/research/README.md` → страница `research`, первой в навигации.
- Ссылки на соседние страницы — относительные (`[отчёт](docx-style-extraction.md)`,
  `[глоссарий](../glossary.md)`): при синке они превращаются в ссылки вики. Ссылки за пределы
  `docs/` оставляйте абсолютными (`https://github.com/…`) — относительные в вики сломаются.
- Файлы, начинающиеся с точки, и страницы без маркера `wiki-sync:managed` синхронизатор не трогает:
  страницы, созданные в вики руками, не удаляются.

## Как добавить артефакт

- Всё, что не `.md` (картинки, `.drawio`, `.pdf`, `.sql`, PoC-скрипты), считается артефактом: попадает
  в авто-блок «Файлы в этой папке» своей страницы и в общий инвентарь **Artifacts**. В авто-перечислении
  всё показывается ссылкой на файл в репозитории, без встраивания.
- Картинку можно встроить по месту — явной ссылкой `![подпись](erd.svg)`. `png`/`svg` рядом с `.drawio`
  трактуется как предпросмотр диаграммы и отдельной строкой не дублируется.
- Крупные бинарники и сгенерированные артефакты сборки в git не кладём — для них есть внешнее хранилище.
- Исключить файл или папку из синка можно строкой-шаблоном в `docs/.wikiignore`
  (например `poc/*` или `*.draft.md`).

## Что собирается скриптами

| Артефакт | Команда | Источник |
|---|---|---|
| `docs/api/` (REST, GraphQL, gRPC) | `make api-docs` | код и аннотации по правилам [`api-docs.toml`](../api-docs.toml) |
| `docs/design/db.sql` | `make db-schema` | Liquibase-чанжлог `backend/api/src/main/resources/db/changelog` |
| `docs/design/schema.svg` и `design/erd.md` | `make db-erd` | тот же чанжлог + `design/layout.yaml` для ручных координат |

Эти файлы в репозитории не правятся: меняйте код, аннотации, `.proto` или конфиг и пересобирайте.
Проверка без записи: `make api-docs-check`, `make db-check`. Прогон DDL на чистой PostgreSQL —
`make db-verify` (нужен docker).

## Как обновляется вики

- **Автоматически:** push в `main` с изменениями в `docs/**`, в скрипте синхронизации или в самом
  workflow. Дополнительно: ручной запуск (`workflow_dispatch`) и еженедельное расписание
  (понедельник, 06:00 UTC) — чтобы подтянуть даты последних коммитов в индекс страниц.
- **Workflow:** `.github/workflows/docs-wiki-sync.yml`, генератор — `.github/scripts/wiki_sync.py`
  (только стандартная библиотека Python).
- **Перед синхронизацией собираются контракты API:** шаг `make api-docs` перегенерирует
  `docs/api/`; если сборка контрактов падает, вики не перезаписывается.
- **Что настроить в репозитории один раз:** включённая Wiki с хотя бы одной страницей, созданной через
  UI (иначе git-репозитория `<repo>.wiki.git` не существует), и секрет `WIKI_TOKEN` — классический PAT
  со scope `repo` (fine-grained-токены прав на вики не дают).
- **Локальный предпросмотр** без публикации:

```bash
make docs-preview      # = make api-docs + wiki_sync в /tmp/wiki-dry, ничего не публикует
make api-docs-check    # проверить, что страницы контрактов соответствуют коду
```

## Чего в каталоге быть не должно

- Секретов, токенов, ключей и конфигурации окружений.
- Документов пользователей и персональных данных: примеры и фикстуры — обезличенные и минимальные.
- Крупных бинарников и сгенерированных артефактов сборки — для них есть внешнее хранилище.
- Правок только в вики и правок руками в `docs/api/`, `design/db.sql`, `design/schema.svg`,
  `design/erd.md` — их перезапишет следующая сборка.
